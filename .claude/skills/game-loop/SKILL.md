# game-loop: 빌드 → 플레이테스트 → 수정 루프

인자(`$ARGUMENTS`)가 있으면 그것이 이번 루프의 구현 목표다. 없으면 `GAME_DESIGN.md`의
"v0.1 완성 조건" 중 아직 ❌인 항목이 목표다.

## 루프 절차

1. **빌드** — `game-builder` 에이전트를 띄워 목표를 구현하게 한다.
   프롬프트에 반드시 포함: 이번 목표, `GAME_DESIGN.md`와 `CLAUDE.md`를 먼저 읽으라는 지시,
   이전 루프에서 발견된 미해결 이슈 목록.
2. **플레이테스트** — `playtester` 에이전트를 띄워 모바일 뷰포트로 실제 플레이시키고
   P0/P1/P2 리포트와 완성 조건 체크리스트 판정을 받는다.
3. **수정** — P0/P1이 있으면 `game-builder`에게 리포트를 그대로 전달해 수정시킨다.
   P2는 사용자에게 목록으로 보고만 하고 다음 루프로 넘긴다.
4. **판정** — 수정 후 P0가 남아 있으면 2번으로 돌아간다 (최대 3회전).
   3회전에도 P0가 남으면 멈추고 사용자에게 상황을 보고한다.

## 규칙

- 빌더와 테스터는 반드시 **다른 에이전트 인스턴스**로 띄운다 (만든 사람이 자기 걸 검사하지 않는다).
- 한 루프의 목표는 작게 — 완성 조건 2~3개 이내.
- 루프가 끝나면 사용자에게: 이번에 완성된 것 / 남은 것 / P2 목록 / 다음 루프 추천 목표를 보고한다.
- 사용자는 디자이너다. 보고에서 개발 용어는 한 줄로 풀어 쓴다.
